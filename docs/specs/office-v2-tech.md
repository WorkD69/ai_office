# AI Office v2 — технический дизайн

Продуктовая часть и приёмка: [../spec.md](../spec.md). Архитектура сейчас: [../architecture.md](../architecture.md).
Решения ADR 0001 (только исходящий relay) и разделение привилегий коллектора остаются в силе.

## Стек

Новых технологий нет: React 19 + Vite + Canvas 2D, Cloudflare Worker (Hono) + Durable Object, Python-коллектор.
Возможное заимствование — движок отрисовки и персонажи Pixel Agents (MIT, персонажи CC0); решается спайком
на этапе дизайна, лицензию мебели и тайлов проверить до заимствования.

## Модули и интерфейсы

### Этап 1 — понятный офис

- **Протокол.** Лента и «требует тебя» перестают нести готовый английский текст: событие получает код
  и параметры, текст собирается в вебе через i18n (ru для владельца, en в демо). Поле `text` остаётся
  как запасной вариант для старых записей ленты в хранилище Durable Object.
  Правило: упавшая задача по расписанию даёт пункт `cron_failed` и событие, но не меняет статус агента
  (так уже устроен коллектор — закрепить тестом протокола и показывать в UI как «одна задача»).
- **Состав.** Агенты с `kind = worker` (обычные боты) рисуются в комнате «Сервисы», а не за столами.
- **Веб.**
  - Две раскладки по ширине: узкая (телефон) — офис на весь экран, комнаты в 2 колонки, нижние вкладки
    Офис / Команда / Сводка, карточка — нижний лист; широкая (ноут) — офис + боковая панель.
  - Mini App разворачивается на весь экран (`expand`, fullscreen там, где клиент поддерживает).
  - Над человечком — значок статуса и короткая табличка `activity`.
  - Карточка агента: описание, тип, статус, последний/следующий запуск, квота за день/неделю, счётчики,
    кнопка «открыть чат» (`openTelegramLink` в Mini App, обычная ссылка `t.me` в браузере).
- **Worker: вход через Telegram Login Widget.** Новый маршрут принимает данные виджета, проверяет
  подпись (ключ = SHA-256 от токена бота, HMAC-SHA-256 по строке проверки, срок `auth_date`), пускает
  только владельца и выдаёт ту же сессию, что и вход через initData. Ручной шаг: `/setdomain` в BotFather.

### Этап 2 — связка с проектами

- **Коллектор: автоподхват.** Сборщик перечисляет профиль `default` и каталоги `profiles/<name>/`
  домашней папки Hermes. В изолированном режиме перечисление делает сервис проекции и передаёт
  экспортёру только имена профилей и разрешённые поля; экспортёр по-прежнему не видит данные Hermes
  (это проверяет ProjectDeploy — не ослаблять).
- **Паспорта** хранятся в репо офиса, по файлу на агента, и едут на сервер вместе с пакетом коллектора
  через обычный деплой ai-office (ProjectDeploy пишет только в папку своего проекта, поэтому другие
  проекты свои паспорта на сервер не кладут). Состав = профили Hermes ∪ паспорта ∪ ручной конфиг (для
  ботов без паспорта). Паспорт дополняет агента: имя, описание, комната, ссылка на чат, счётчики.
  В профилях Hermes описаний нет: агент без паспорта получает только имя профиля,
  `room = "newcomers"` и `hasPassport = false`. Валидация паспортов — тестом в CI офиса.
- **Значения счётчиков** приходят в рантайме от самих проектов: проект пишет маленький файл со
  значениями в своей папке, путь указан в паспорте. Сервис проекции читает только пути из паспортов
  (allow-list) и только ключи, объявленные в паспорте, не больше трёх.
- **Харнесс** (вне этого репо): правило в глобальных правилах и в скилле new-project —
  «агент/бот на VPS → создай или обнови паспорт в репо офиса (PR) и задеплой ai-office».

### Этап 3 — квота Claude и уведомления

- **Квота Claude.** Скрипт статусной строки на ноуте отправляет `rate_limits` на новый маршрут Worker
  с отдельным секретом (`CLAUDE_QUOTA_TOKEN`); токены Anthropic никуда не передаются. Durable Object
  хранит последний снимок, состояние офиса отдаёт список квот. Не чаще одного запроса в минуту
  (дедупликация на стороне скрипта). Статусная строка у пользователя управляется home/install.py —
  встраиваться через харнесс, не правкой профиля руками.
- **Уведомления.** Durable Object при каждом снимке и при потере коллектора проверяет правила:
  агент офлайн дольше 15 минут, квота выше 90 %, коллектор молчит дольше 15 минут (пороги настраиваемые). Сообщение владельцу —
  через Bot API `sendMessage` существующим токеном бота. Одна причина — не чаще раза в 12 часов,
  общий потолок в сутки настраиваемый. Тексты на русском.

## Данные

Durable Object (SQLite): новые записи — последний снимок квоты Claude; журнал отправленных уведомлений
(ключ причины, время) для дедупликации. Существующая лента: старые записи с `text`, новые с `code`.

## Контракты

Изменения протокола (zod остаётся источником правды; Python-коллектор сверяется контрактным тестом).
Версию протокола повышаем до 2 одновременно с выкладкой Worker и коллектора.

```ts
// событие ленты и пункт «требует тебя»: код + параметры, текст собирает веб
FeedEvent  = { id, at, agentId | null, level: 'info'|'warn'|'error',
               code: 'joined'|'left'|'status'|'activity'|'cron_ran',
               params: Record<string, string | number>,   // имена, статус, имя задачи, исход
               text?: string }                             // только старые записи
InboxItem  = { id, agentId, kind: 'approval'|'error'|'cron_failed'|'offline',
               params: Record<string, string | number>, since | null }

// агент: новые поля (всё опционально, заполняются паспортом)
Agent += { summary: string(≤120) | null,      // «ищет стажировки, раз в день»
           chatUrl: 'https://t.me/…' | null,  // только домен t.me
           counters: { label: string(≤40), value: number, period?: 'day'|'week' }[] (≤3),
           hasPassport: boolean,
           project: string(≤48) | null }

// снимок: квоты — список вместо одного значения
Snapshot.quota: Quota | null   →   Snapshot.quotas: Quota[] (≤4)
// OfficeState добавляет квоту Claude из Worker к квотам из снимка
```

Паспорт агента (файл в репо офиса, формат TOML):

```toml
id = "opportunity-hunter"          # ^[a-z0-9][a-z0-9-]{0,47}$, совпадает с профилем Hermes или unit
name = "Охотник"                   # ≤ 40
summary = "Ищет стажировки и вакансии, раз в день"   # ≤ 120
room = "opportunities"             # ^[a-z0-9-]{1,32}$
kind = "llm"                       # llm | worker
source = "hermes"                  # hermes | systemd
profile = "opportunity-hunter"     # для source = hermes
units = []                         # для source = systemd
chat_url = "https://t.me/<bot>"    # только t.me
values_file = "/opt/<project>/…/office-counters.json"   # файл значений в папке проекта
[[counters]]                       # ≤ 3
key = "vacancies_found"
label = "Найдено вакансий"
period = "week"
```

Приём квоты Claude (ноут → Worker), `Authorization: Bearer <CLAUDE_QUOTA_TOKEN>`:


## Seams для тестов

1. **Протокол (чистые функции)** — главный seam. Снимок до/после → коды событий и пункты «требует тебя»;
   правило «задача упала ≠ агент сломан»; сборка состава (профили ∪ паспорта ∪ конфиг, «Новенькие»);
   валидация паспорта и `chatUrl`. Прецедент: тесты derive и контрактный тест между TS и Python.
2. **HTTP API Worker** — вход через виджет (верная подпись, чужой пользователь, просроченный
   `auth_date`), приём квоты (без токена 401, неверная схема 400, повтор не дублирует), уведомления
   (порог, дедупликация 12 ч, суточный потолок) с фейковым Bot API. Прецедент: тесты app, telegram,
   core с фейком рантайма.
3. **Сборщик снимка коллектора** — синтетическая домашняя папка Hermes с несколькими профилями и
   паспортами → ожидаемый состав; золотые файлы. Прецедент: тесты snapshot и golden.
4. **Веб** — чистые функции раскладки (узкая/широкая, комнаты 2 колонки, «Сервисы», «Новенькие») и
   паритет i18n для всех кодов событий; один визуальный проход в демо-режиме на 390 px и 1440 px
   (Playwright, скриншоты). Прецедент: тесты layout, i18n, demo.

Хороший тест здесь проверяет внешнее поведение: что увидит пользователь или что вернёт маршрут, а не
внутреннее устройство модулей. Все данные синтетические.
